# Spring AI Multi-Agent Pipeline Guide

This skill specifies the architecture, contracts, and patterns for the four-agent pipeline and the deterministic orchestrator within MeetingMind, built with **Spring AI**.

---

## 1. Pipeline Architecture & Data Flow

MeetingMind orchestrates four specialized agents in a deterministic sequence. Each agent performs a single transformation, producing strongly typed outputs consumed by downstream agents or verification gates.

```text
Raw Meeting Transcript
           │
           ▼
┌────────────────────────────────────────────────────────┐
│                  MeetingOrchestrator                   │
│                                                        │
│  [1. SummarizerAgent]                                  │
│      Input:  Raw Transcript                            │
│      Output: MeetingSummary (Overview, Key Decisions)  │
│                                                        │
│  [2. ExtractorAgent]                                   │
│      Input:  Raw Transcript + MeetingSummary           │
│      Output: List<ActionItemDto> (Task, Owner, Due)    │
│                                                        │
│  [3. DrafterAgent]                                     │
│      Input:  MeetingSummary + List<ActionItemDto>      │
│      Output: EmailDraftDto (Subject, Body, Next Steps) │
│                                                        │
│  [4. ReviewerAgent]                                    │
│      Input:  Transcript + ActionItems + EmailDraft     │
│      Output: ReviewResultDto (Passed, Flags, Missing)  │
└────────────────────────────────────────────────────────┘
```

## 2. Agent Contracts & Responsibilities

### 2.1 Summarizer Agent (`ai/agent/summarizer/`)
- **Responsibility**: Synthesize meeting discussions into a high-level executive summary and catalog key decisions.
- **Input**: `String transcript`
- **Output Record**:
  ```java
  public record MeetingSummary(
      String title,
      String overview,
      List<String> keyDecisions,
      List<String> discussionTopics
  ) {}
  ```
- **Constraint**: Must not attempt to extract detailed individual action items or write follow-up messages.

### 2.2 Extractor Agent (`ai/agent/extractor/`)
- **Responsibility**: Extract discrete, actionable deliverables with clear ownership, deadlines, and context.
- **Input**: `String transcript`, `MeetingSummary summary`
- **Output Record**:
  ```java
  public record ExtractedActionItemList(
      List<ExtractedActionItem> items
  ) {}

  public record ExtractedActionItem(
      String description,
      String assignee,
      String dueDate,
      String context
  ) {}
  ```
- **Constraint**: Must rely strictly on explicit or directly implied commitments in the transcript. Must not fabricate task owners.

### 2.3 Drafter Agent (`ai/agent/drafter/`)
- **Responsibility**: Compose a professional, ready-to-send follow-up email.
- **Input**: `MeetingSummary summary`, `List<ExtractedActionItem> items`
- **Output Record**:
  ```java
  public record EmailDraft(
      String subject,
      String body,
      List<String> recipientSuggestions
  ) {}
  ```
- **Constraint**: Must use the action items generated by the Extractor Agent. Must never invent new tasks or commitments.

### 2.4 Reviewer Agent (`ai/agent/reviewer/`)
- **Responsibility**: Perform automated fact-checking, hallucination detection, and completeness auditing.
- **Input**: `String rawTranscript`, `List<ExtractedActionItem> actionItems`, `EmailDraft emailDraft`
- **Output Record**:
  ```java
  public record ReviewResult(
      boolean verified,
      List<String> hallucinatedItems,
      List<String> missedItems,
      List<String> dateOrAssigneeDiscrepancies,
      String commentary
  ) {}
  ```
- **Constraint**: Acts strictly as a critique and verification layer. Does not alter outputs directly; reports findings to the orchestrator.

## 3. Orchestration Engine (`ai/orchestrator/`)

The `MeetingOrchestrator` is a Java component responsible for pipeline execution.

### Orchestration Rules
1. **Explicit Control Flow**: The orchestrator invokes agents sequentially. Direct agent-to-agent communication (`Agent A ➔ Agent B`) is **strictly prohibited**.
2. **State Encapsulation**: The orchestrator manages an analysis context object (`MeetingAnalysisContext`) tracking inputs, intermediate results, timestamps, and error states.
3. **Asynchronous Execution**: The orchestrator must run asynchronously (using `@Async`) in the background, updating the `Meeting` entity's granular status (`SUMMARIZING`, `EXTRACTING`, etc.) as it progresses, without blocking the initial HTTP request.
4. **Stage Toggling**: During development, testing, or rate-limited runs, each stage must support independent execution or bypassing:
   ```yaml
   meetingmind:
     ai:
       pipeline:
         summarizer-enabled: true
         extractor-enabled: true
         drafter-enabled: true
         reviewer-enabled: true
   ```

## 4. Spring AI Integration Patterns

### 4.1 Client Abstraction & Model Configuration
MeetingMind uses Spring AI's OpenAI-compatible client configured to interact with the Grok/xAI endpoint.

```yaml
# application.yml (Phase 1+)
spring:
  ai:
    openai:
      api-key: ${GROK_API_KEY}
      base-url: https://api.x.ai/v1
      chat:
        options:
          model: grok-beta
          temperature: 0.2
```

### 4.2 Fluent `ChatClient` Usage
Agents use the Spring AI `ChatClient` abstraction to ensure vendor-neutral model interactions:

```java
// Example agent pattern
@Component
public class SummarizerAgent {

    private final ChatClient chatClient;
    
    @Value("classpath:prompts/summarizer/summarizer-prompt.st")
    private Resource promptTemplate;

    public SummarizerAgent(ChatClient.Builder chatClientBuilder) {
        this.chatClient = chatClientBuilder.build();
    }

    public MeetingSummary summarize(String transcript) {
        return chatClient.prompt()
            .user(u -> u.text(promptTemplate).param("transcript", transcript))
            .call()
            .entity(MeetingSummary.class);
    }
}
```

### 4.3 Structured Output Parsing
- Always use Spring AI's structured output conversion (`.entity(TargetRecord.class)`) or `BeanOutputConverter<T>`.
- Avoid manually parsing JSON responses with raw regular expressions or unstructured string slicing.

### 4.4 Externalized Prompt Templates
- Prompt files reside exclusively in `src/main/resources/prompts/<agent>/` using StringTemplate format (`.st`).
- System instructions, response constraints, and output format schemas must remain in template files, not hardcoded inside Java strings.

## 5. Cost & Rate Limit Strategy

To operate strictly within free-tier and educational constraints:
- **Low Call Footprint**: A complete meeting analysis requires exactly 4 LLM calls (1 per agent).
- **Conservative Temperature**: Use low temperatures (`0.0` - `0.3`) for Extractor, Drafter, and Reviewer to minimize non-deterministic variance and token waste.
- **Fail-Fast Validation**: Check for empty or malformed transcripts before dispatching calls to the LLM.
- **No Unapproved Paid Services**: Never configure OpenAI paid endpoints, Anthropic endpoints, or paid embedding APIs.

## 6. Anti-Patterns & Pitfalls

| Pitfall / Anti-Pattern | Why It Fails | Recommended Pattern |
| :--- | :--- | :--- |
| **All-in-one Single Prompt** | Low accuracy, unreviewable hallucinations, missed tasks. | Modular 4-agent pipeline with dedicated verification. |
| **Hardcoded Prompts in Java** | Makes prompt tuning tedious, violates separation of concerns. | External `.st` templates under `resources/prompts/`. |
| **Agent-to-Agent Direct Calls** | Creates tight coupling, prevents stage-level mocking and testing. | Deterministic orchestration via `MeetingOrchestrator`. |
| **Raw Entity Mutation** | Couples AI responses directly to JPA database tables. | Agent I/O uses immutable records/DTOs; services handle persistence. |

---

## 7. Verification Checklist

When developing or modifying agents:
- [ ] Does each agent map to a single defined responsibility?
- [ ] Are input/output contracts defined as strongly typed Java records?
- [ ] Is prompt text stored under `src/main/resources/prompts/<agent>/`?
- [ ] Is `ChatClient` used without hardcoded vendor-specific client libraries?
- [ ] Can the pipeline stage be enabled or disabled via configuration flags?
